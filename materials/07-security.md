# 7. Security(15分・ハンズオン)

対象: これまでのセクションで各自が変更した `samples/common-web`(MiniTask)一式。

## 脅威モデル(3分で話す)

エージェント特有の脅威、4点:
- **Prompt injection**: Web取得コンテンツやファイル内容に埋め込まれた指示にエージェントが従ってしまう
- **サプライチェーンリスク**: MCPサーバー/skillは任意コード実行に等しい。導入前の検証が要る
- **秘密情報の扱い**: `.env`のコミット漏れ、コード内フォールバック値など
- **レビュー前マージ禁止**: エージェントの出力を無検証でmergeしない運用ルール

## 手順

### Step 1: `/security-review` を自分の差分に実行(7分)

**やること**

1. Claude Codeで `/security-review` を実行させる(各自、2〜6セクションで自分が MiniTask に加えた変更が対象)

**期待される発見(見つかれば講師から深掘りする)**:
- `routes/tasks.js` の `requireAdminKey` が `"changeme123"` という弱いデフォルト値にフォールバックしている(`.env` を作り忘れても動いてしまう)
- 5. Log Engineering で設定した hook のログは `actor: "agent"` を常に固定値で出力している(= 本当に「誰が」操作したかは記録できていない。Claude Codeのhookには人間のユーザー識別情報は渡ってこないため)

見つからなかった場合の誘導質問: 「管理者用の操作、`.env` を作り忘れたらどうなる?」「ログの`actor`フィールド、本当に『誰が』まで分かる?」

**✅ 確認(これが出たら成功)**: `/security-review` の出力に、上記のどちらか(または両方)が指摘として挙がっている。

2. 見つけた問題を、実際にその場で1つ直させる(例: フォールバック値を廃止し、`ADMIN_KEY` 未設定なら起動時にエラーで落とすようにする)

**✅ 確認(これが出たら成功)**: 修正後、`.env` を一時的にリネームして `npm start` すると、起動時にエラーで落ちる(弱いフォールバックで動いてしまわない)。

### Step 2: 権限スコープの再点検(3分)

**やること**

1. 2. Harness Engineering で絞り込んだ `.claude/settings.json` の `permissions.allow` を見直させる

**問いかけ**: 「今のスコープで、まだ広すぎる箇所はないか」を自問させる。ここでは新しい発見が無くてもよい(前セクションの学びが定着しているかの確認が目的)。

### Step 3: サプライチェーンチェックリスト適用(3分)

**やること**

1. 配布資料(`handouts/security-checklist.md`)を開かせる
2. 自分が普段使っている MCP サーバー/skill を1つ選んで、以下3点を当てはめさせる:
   - 提供元は信頼できるか(OSS なら star 数・メンテ状況、社内製なら管理者が明確か)
   - 実行時にどこまでのファイル/ネットワークアクセスを要求するか
   - 導入前にコードを読んだか、読める分量か

### まとめ(2分)
「今日直した1件は氷山の一角。エージェント運用の恒久ルールとして、生成物は必ずレビューしてからmergeする」を強調して締める。

## 講師メモ
- Step 1 で誰も問題を見つけられない場合に備え、`samples/common-web/INSTRUCTOR_NOTES.md` の仕込み一覧をいつでも参照できるようにしておく
- `/security-review` の出力がトレーニーごとに変わる(直前の変更内容に依存する)ため、講師は各自の画面を巡回して個別にフォローする時間として使う
- 初心者トレーニーには「`/security-review` はコマンドを打つだけ。何が出てくるかは分析結果を読むだけでOK、自分でコードを探す必要はない」と最初に一言添える
