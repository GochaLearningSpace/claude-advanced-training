# 4. Self-host(ローカルLLM)(9分・講師デモのみ)

> イントロのライブセットアップに時間を回したため12分→9分に短縮(`README.md` アジェンダ参照)。元々あったAWSデプロイのデモ(Step 3)は削除し、ローカルLLMのデモをその分拡張した

トレーニー操作なし。環境構築(モデルのダウンロード等)に時間がかかるため講師の手元のみで実演。目的は「原理を知っておけば必要になった時に迷わない」状態を作ること。

## 構成

### Step 1: なぜ扱うか(1分)

今使っている Claude Code は API 経由。だが実務では「機密データを外に出したくない」「ネットが無い環境でも動かしたい」という要求が必ず出てくる。今日はオープンソースモデルを実際にダウンロードして手元で動かして見せる、判断基準を持ち帰ってもらう。

### Step 2: ローカルLLMを実際に動かす(8分)

対象ツール: [Ollama](https://ollama.com/)。モデルは [Qwen2.5 1.5B](https://ollama.com/library/qwen2.5)(オープンソース、軽量、日本語対応あり)。

**事前準備(講師、当日までに完了させておく。ライブでは絶対にやらない)**:
```bash
# Ollamaインストール(初回のみ)
winget install --id Ollama.Ollama -e

# モデルのダウンロード(初回のみ、ネットワーク次第で数分かかる)
ollama pull qwen2.5:1.5b
```

#### Step 2a: ダウンロード済みのモデルを見せる(2分)

- `ollama list` でローカルに入っているモデル一覧を見せる(ダウンロード自体はライブでやらず、「一度ダウンロードすれば、あとは手元のファイルとして存在する」ことを強調)
- モデルサイズ(1.5Bモデルで約1GB)に触れ、「クラウドの巨大モデルとは違い、手元のGPU/CPUで動く規模」であることを説明

#### Step 2b: 実際に質問して応答を見せる(3分)

Ollamaサーバーをあらかじめ起動しておく(`ollama serve`、バックグラウンド常駐)。ターミナルから直接APIを叩いて見せる:

```bash
curl -s http://localhost:11434/api/chat -d '{
  "model": "qwen2.5:1.5b",
  "messages": [{"role": "user", "content": "こんにちは、調子はどうですか？"}],
  "stream": false
}'
```

- クラウドAPIと同じ「HTTPでプロンプトを送って応答を受け取る」構造であることを見せる(呼び出し方の形は同じ、エンドポイントが `localhost` なだけ)
- 軽量モデルなので応答の質は限定的(日本語がやや怪しくなることもある)→ これ自体が「モデル性能: ハードウェア制約あり」というトレードオフの実例になる

#### Step 2c: ネットワークなしで動くことを実演(3分)

**見せ場**: 講師のPCのWi-Fiをその場で切り、同じコマンドをもう一度叩く。

```bash
curl -s http://localhost:11434/api/chat -d '{
  "model": "qwen2.5:1.5b",
  "messages": [{"role": "user", "content": "Hello"}],
  "stream": false
}'
```

- Wi-Fiを切っても全く同じように応答が返ることを見せる
- 理由を説明: モデルの重みは既にローカルのファイルとして存在しており、推論(計算)は手元のCPU/GPUだけで完結する。一度ダウンロードした後は外部通信が一切発生しない
- トレードオフを口頭で整理:

  | 観点 | クラウドAPI | ローカルLLM |
  |------|-----------|------------|
  | コスト構造 | 従量課金 | 初期投資(GPU等)+電力 |
  | レイテンシ | ネットワーク依存 | ローカル完結で安定 |
  | データ主権 | 外部送信あり | 外部に出さない(今まさに実演した通り) |
  | モデル性能 | 最新最大モデル使える | ハードウェア制約あり |

- 「トレーニーの皆さんの手元でも、`ollama pull` 一発で同じことができる」ことを明言(今日はやらないだけ)

### まとめの判断基準(口頭)

- 機密データを扱う / 規制業界 / オフライン環境が必要 → self-host(ローカルLLM)を検討
- スピード優先・最新最大モデルの性能が必要 → クラウドAPI
- 中間: 機密性の低いタスクはクラウドAPI、機密データに触れる部分だけローカルLLMに任せる、というハイブリッドが現実解になりやすい

## トラブルシューティング: `ollama: command not found`

インストール直後、同じターミナルで `ollama` コマンドが見つからないことがある(インストーラーがWindowsのPATHを更新しても、既に開いているターミナルには反映されないため)。

**応急処置(その場ですぐ使う)**:
```bash
# フルパスで直接実行する
"/c/Users/silve/AppData/Local/Programs/Ollama/ollama.exe" list

# このセッションだけPATHに追加する
export PATH="$PATH:/c/Users/silve/AppData/Local/Programs/Ollama"
ollama list
```

**恒久対応**: ターミナルを一度閉じて開き直す(新しいシェルなら更新済みのWindows PATHを読み込む)。
