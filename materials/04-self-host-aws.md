# 4. Self-host + AWS デプロイ(12分・講師デモのみ)

トレーニー操作なし。ライセンス・環境構築の都合で講師の手元のみで実演。目的は「原理を知っておけば必要になった時に迷わない」状態を作ること。

## 構成

### Step 1: なぜ扱うか(2分)

今使っている Claude Code は API 経由。だが実務では「ローカルLLMで動かしたい」「自社インフラにデプロイしたい」という要求が必ず出てくる。今日は動かして見せるだけ、判断基準を持ち帰ってもらう。

### Step 2: ローカルLLM デモ(5分)

講師側で事前に用意済みの環境:
- Ollama(または同等のローカル推論環境)でモデルを起動している状態を見せる
- API呼び出し先を自分のツールからローカルエンドポイントに切り替えられる、という構造だけ見せる(実際の切り替え操作は事前収録でも可)
- Trade-off を口頭で整理:
  | 観点 | クラウドAPI | ローカルLLM |
  |------|-----------|------------|
  | コスト構造 | 従量課金 | 初期投資(GPU等)+電力 |
  | レイテンシ | ネットワーク依存 | ローカル完結で安定 |
  | データ主権 | 外部送信あり | 外部に出さない |
  | モデル性能 | 最新最大モデル使える | ハードウェア制約あり |

### Step 3: AWS デプロイ デモ(5分)

`samples/common-web`(MiniTask)を講師の AWS 環境に実際にデプロイして見せる。
- デプロイ先候補(講師の準備状況に応じて選択): App Runner / Elastic Beanstalk / EC2 + PM2 のいずれか
- 見せる流れ: ローカルで動いていたものと同じ画面が、公開URLでも動く
- 「トレーニーの皆さんの手元でも、原理的には同じ手順でできる」ことを明言(今日はやらないだけ)

### まとめの判断基準(口頭)

- 機密データを扱う / 規制業界 → self-host 検討
- スピード優先・少人数 → クラウドAPI+マネージドデプロイ
- 中間: 推論はクラウドAPI、周辺データは自社インフラに置く、というハイブリッドが現実解になりやすい
