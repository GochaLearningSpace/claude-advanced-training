# Self-host(ローカルLLM)

## 一言で
今使っているClaude CodeはAPI経由。だが実務では「機密データを外に出したくない」「ネットが無い環境でも動かしたい」という要求が必ず出てくる。オープンソースモデルを自分のPCにダウンロードして動かす、という選択肢の原理を知っておけば必要になった時に迷わない。

## インストール方法(Ollama)

```bash
# Windows
winget install --id Ollama.Ollama -e

# Mac
brew install ollama

# Linux
curl -fsSL https://ollama.com/install.sh | sh
```

インストール後、モデルをダウンロードする(初回のみ、サイズとネットワーク次第で数分かかる):

```bash
ollama pull qwen2.5:1.5b
```

`qwen2.5:1.5b` は軽量(約1GB)なオープンソースモデルで、日本語にも対応している。GPUが無い/非力なPCでも動く規模を選ぶのがポイント(今日のデモ機はGTX 1650・VRAM 4GBで動作確認済み)。

## 確認方法

```bash
# ダウンロード済みモデルの一覧
ollama list

# サーバーが起動しているか確認(起動していなければ `ollama serve` で起動)
curl http://localhost:11434/api/tags

# 実際に質問してみる
curl -s http://localhost:11434/api/chat -d '{
  "model": "qwen2.5:1.5b",
  "messages": [{"role": "user", "content": "こんにちは、調子はどうですか？"}],
  "stream": false
}'
```

**データ主権を実際に確かめる方法**: Wi-Fiをオフにしてから同じcurlコマンドをもう一度叩く。同じように応答が返れば、推論が完全にローカル完結している証拠(モデルの重みは既にローカルのファイルとして存在し、外部通信は発生しない)。

## クラウドAPI vs ローカルLLM

| 観点 | クラウドAPI | ローカルLLM |
|------|-----------|------------|
| コスト構造 | 従量課金 | 初期投資(GPU等)+電力 |
| レイテンシ | ネットワーク依存 | ローカル完結で安定 |
| データ主権 | 外部送信あり | 外部に出さない |
| モデル性能 | 最新最大モデル使える | ハードウェア制約あり(軽量モデルは日本語品質が不安定になることがある) |

クラウドAPIもローカルLLMも「HTTPでプロンプトを送って応答を受け取る」構造は同じ。違うのはエンドポイントが外部か`localhost`かだけ。

## 判断基準
- 機密データを扱う / 規制業界 / オフライン環境が必要 → self-host(ローカルLLM)を検討
- スピード優先・最新最大モデルの性能が必要 → クラウドAPI
- 中間: 機密性の低いタスクはクラウドAPI、機密データに触れる部分だけローカルLLMに任せるハイブリッドが現実解になりやすい
